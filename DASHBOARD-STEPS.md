The Android commits do not apply backend changes. `kavach-r2.sql` and the migration are identical: run ONE, not both. SQL is transactional and must be run as database owner. Back up first. The phone-member schema is newer than the public SQL source; export current function definitions before deploying. Test on a staging copy first.

## Compatibility and limits

- Apply SQL before using the new Android assignment flow (`p_expected_assignee` / `p_check_expected`). Old 2-argument callers are supported by the new defaults.
- Home setup now selects existing property inventory only. A household-sharing or admin override flow needs an explicit product decision; this patch refuses another profile's occupied flat.
- Off-duty self-claim and admin specialty bypass remain intentional. Admin assignment now refuses off-duty or wrong-specialty responders rather than silently accepting them.
- Responder society contact read access is unchanged. Narrowing it is a separate coordination/privacy decision.
- Production Supabase changes are not verified until the owner applies the SQL and completes smoke checks. Local SQL validation is not a production deployment.
